# Ежедневная подготовка и обсуждение с ИИ — реализация

Основание: пользователь попросил исправить замечания `AUDIT-AP2-2026-10-14.md` и реализовать удобное обсуждение в ChatGPT без множества окон. Обычные локальные решения авторизованы в AGENTS.md; повторное утверждение не требуется.

## Решение

Сохранить статическое приложение. Исправления разделены по владельцам файлов; исходные экзамены и AP1 не изменять. Для ИИ — общий модуль передачи текста: ChatGPT по умолчанию, сохранённая личная ссылка отдельно для каждого экзамена, явное копирование без открытия. Первое обсуждение может открыть окно, последующие не создают его автоматически повторно, если браузер потерял доступ к прежнему. Пользователь вставляет и отправляет текст сам. Приложение не получает доступ к истории ChatGPT, не отправляет запросы к платному API и не помещает экзаменационный текст в URL. Ссылка беседы копируется из адресной строки, публичный shared-link не нужен.

## Особые проверки

Повреждённое и переполненное хранилище не должны приводить к тихой потере исходных данных. Вкладка ИИ может потерять доступную приложению ссылку из-за браузерной изоляции; это не повод автоматически открывать следующую. Быстрые повторные клики не дублируют окна. Отправка сообщения и оценка ИИ остаются действиями пользователя, оценка не считается официальным ключом IHK.

## Источники технических ограничений

Exa недоступна, использован доступный веб-поиск. Прочитана документация MDN: [открытие и повторное использование окон](https://developer.mozilla.org/en-US/docs/Web/API/Window/open), [ограничение взаимодействия разных сайтов](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Same-origin_policy). Автоматически читать URL созданного чата и вставлять текст в его DOM из локального приложения нельзя обещать. Возврат в сохранённую беседу и копирование доступны без такого доступа.
